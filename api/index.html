Per-Game Endpoints

Every published game gets its own namespace. The pattern is consistent — only the slug changes.

# Metadata (JSON) /api/rules/{slug}/meta.json # Full rulebook content (Markdown, frontmatter stripped) /api/rules/{slug}/rulebook.md # Individual variant rules /api/rules/{slug}/variants/{variant}.md # Component hub games /api/rules/{slug}/games/{game}.md # RPG sub-pages (rules, classes, spells, etc.) /api/rules/{slug}/pages/{section}/{page}.md # Data files (passthrough) /api/rules/{slug}/data/{file}.json # Oracle tables (per-game aggregate) /api/rules/{slug}/oracles.json

How It Works

The API is a build artifact. No server, no database, no Worker. Adding a game or variant to the source automatically exposes it at a predictable URL on the next deploy.

# Source (you edit this) games/backgammon/content/variants/standard.md # API output (auto-generated) dist/api/rules/backgammon/variants/standard.md # Live URL (GitHub Pages serves it) https://rules.moddable.games/api/rules/backgammon/variants/standard.md

To extend the API with new metadata fields, add them to rulebook frontmatter. The build reads whatever is there — no registration, no schema to update.
